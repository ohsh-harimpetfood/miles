01 / WHO I AM

현실의 운영 문제를 시스템으로 바꾸는 사람.

제조 현장에서 출발해 생산과 품질, 공정과 재고를 직접 다뤄왔다. 이후 MES 구축과 운영을 경험하면서 문제를 바라보는 범위가 현장에서 프로세스로, 프로세스에서 시스템과 데이터로 확장됐다.

지금은 현장에서 실제로 일이 어떻게 움직이는지 이해하고, 그 흐름을 구조화한 뒤, 필요한 경우 직접 실행 가능한 시스템으로 구현한다.

현장을 알고, 구조를 설계하고, 필요하면 직접 만든다.

Manufacturing · MES · WMS · ERP · Data · AI · Automation

WHO FIRST

프로젝트를 보여주기 전에, 어떤 현실에서 출발했고 어떤 방식으로 문제를 다루는 사람인지 먼저 설명한다.

I DID NOT START AS A DEVELOPER

나는 개발자로 출발하지 않았다.

2009년부터 제조 현장에서 일해왔다. 생산과 품질 업무를 통해 라인, 설비, 원료, 공정조건, 생산실적, 재고, 품질 이상과 같은 물리적인 운영 문제를 먼저 경험했다.

소프트웨어를 먼저 배우고 현장으로 간 것이 아니라, 현장에서 오래 일하다 보니 기존 시스템만으로 해결되지 않는 문제들이 계속 보이기 시작했다.

  • 왜 현장에서는 알고 있는 사실이 시스템에서는 보이지 않는가?
  • 왜 데이터가 있는데 사람이 다시 정리해야 하는가?
  • 왜 시스템을 구축했는데 운영 방식은 바뀌지 않는가?
  • 왜 반복해서 발생하는 문제를 계속 사람이 감당해야 하는가?

이 질문들이 내가 시스템을 만드는 쪽으로 이동하게 된 출발점이었다.

HOW I OPERATE

현장과 기술 사이에서 세 가지 역할을 동시에 한다.

01

Operator

실제 제조 운영을 경험했다. 작업자, 설비, 공정, 원료, 실적, 재고, 마감과 같은 물리 세계의 제약을 시스템 밖의 변수로 취급하지 않는다.

02

Architect

문제를 화면 하나의 기능으로 보지 않는다. 업무 흐름, 데이터 구조, 기준정보, 시스템 경계, 책임과 인터페이스를 함께 본다.

03

Builder

분석과 기획에서 멈추지 않는다. 필요하면 SQL, Python, Apps Script, Streamlit, Web Application과 데이터베이스까지 내려가 생각을 실행 가능한 상태로 만든다.

목적은 코드를 작성하는 것이 아니다. 생각을 실행 가능한 상태까지 밀어 넣는 것이다.

AI AND IMPLEMENTATION

AI는 내 판단을 대신하는 것이 아니라, 구현 가능한 범위를 넓힌다.

문제 정의, 업무 규칙, 운영 제약, 아키텍처 판단과 최종 검증은 사람이 통제한다.

구현, 대안 탐색, 반복 코딩, 문서화와 분석 보조에는 AI를 적극적으로 사용한다.

Implementation is delegated. Intent is retained.

Autonomous AI operation 또는 formal methodology status를 주장하지 않는다.

POSITION

현실에서 발생하는 운영 문제를 발견하고, 그것을 이해 가능한 구조로 만들고, 실행 가능한 시스템으로 바꾸는 것.

Execution Systems

ERP · SAP PI · master data · process design

Data & Intelligence

Automation

AI-native Work
