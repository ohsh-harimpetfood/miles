01

PROBLEM / FIRST TRY / PIVOT

FROM A FIELD PROBLEM TO A WORKING SYSTEM.

창고의 위치, 품목, 재고 상태 확인은 랙카드와 현장 탐색, 사람 간 확인에 크게 의존했습니다. 위치와 품목이 맞지 않거나 재고를 찾고 다시 확인하는 일이 운영 부담으로 이어졌습니다.

그래서 새 화면을 만드는 것보다, 실제 창고의 상태와 시스템의 기록이 서로 맞도록 만드는 것을 먼저 해결해야 했습니다.

HANDWRITTEN RACK CARDS LOCATION / ITEM MISMATCH HARD TO FIND STOCK REPEATED CHECKING STOCKTAKE

APPSHEET WAS THE FIRST WORKING TEST.

위치(Location), 품목(Item), 이동 기록(Transaction)을 연결하고 QR로 현장에서 처리하는 방식을 먼저 시험했습니다. AppSheet는 최종 시스템이 아니라, 데이터 구조와 모바일 작업 방식이 실제 현장에서 통하는지 빠르게 확인하기 위한 첫 실행안이었습니다.

운영 요구가 늘면서 첫 시험에서 확인한 문제와 데이터 구조는 유지하고, 화면 제어와 성능, 배포, 확장성을 높이기 위해 직접 만든 웹 시스템으로 옮겼습니다. 처음부터 다시 만든 것이 아니라, 현장에서 확인한 방식을 더 크게 운영할 수 있도록 확장한 것입니다.

02

HOW / DAILY WORK FLOW

ONE FLOW FROM INBOUND TO HISTORY.

INBOUND→INVENTORY→MOVEMENT→OUTBOUND→HISTORY

입고부터 재고·이동·출고·이력까지 하나의 흐름으로 연결했습니다. 품목 기준정보, 사용자 권한, 재고 조정, 실사와 확인 기능도 같은 운영 흐름 안에 배치했습니다.

재고를 일부만 옮기거나 전부 옮기고, 같은 위치에서 합치는 경우에도 포장 정보를 유지하도록 이동 규칙을 확장했습니다.

03

HOW / WAREHOUSE ↔ SYSTEM

MAKE THE SYSTEM MATCH THE REAL WAREHOUSE.

WAREHOUSE LOCATION→LOCATION ID→QR / RACK CARD→MOVEMENT→INVENTORY→WAREHOUSE MAP

실제 창고 위치마다 관리 가능한 ID를 부여하고 QR·랙카드·재고 이동 기록·창고 맵을 연결했습니다. 여러 형태의 보관 공간과 한 위치에 여러 재고가 있는 경우도 화면에서 확인할 수 있도록 확장했습니다.
